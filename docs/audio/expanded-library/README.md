# Expanded audio library — 2026-11-26

The owner explicitly authorizes publishing automatically verified recordings and all three Arabic books without a further confirmation or human-review gate in this phase. See [the phase](../../agent/phases/AUDIO_LIBRARY_EXPANSION_2026_11_26.md). This is publication authority, not a claim that listening or scholarly review occurred.

The [evidence manifest](evidence.json) pins 459 source recordings after complete MP3 decoding, exact byte size/SHA-256 checks and measured durations. Quran sources are the selected Hafs/Murattal MP3Quran readings 112, 118 and 92; their source inventory and per-recording verse coverage are checked against the app's unchanged complete semantic Mushaf corpus. OpenDua v0.0.4 transcripts bind matching v0.0.2 Muhammad Jumah files to explicit existing asset segments or new exact-content assignments. Formatting normalization never substitutes Arabic words. Reused media is deduplicated by immutable identity. Existing default voices and previously approved timing annotations are preserved.

Four Quran candidates are excluded: Minshawi At-Tawbah and Hussary Al-Fatihah lack complete provider verse coverage; Minshawi At-Tur and Hussary Al-Anbiya have provider timing outside the measured file range. Other verified recordings retain playback coverage for all 114 surahs. No provider timing is installed as app word highlighting. The exact source/timing hashes and source URLs remain in the manifest; raw intake and diagnostic traces remain under the local release evidence directory.

Automated source/identity/range and decode checks establish the tested mapping and media integrity. Independent unprompted Whisper transcription is collected as diagnostic evidence; the known accepted control also produces recognition errors. Speech recognition is not proof of pronunciation, full religious-source accuracy or every spoken word in a long recording. Unmatched app wording is never attached to a merely similar recording.

The manual **Ingest verified audio library** workflow uses encrypted, temporary repository configuration to copy only pinned originals into existing immutable audio-host paths. It rejects changed source bytes, refuses different existing objects, and verifies complete public SHA-256, MIME, production CORS and byte ranges. Remove the temporary repository secret after ingestion. The complete Quality gate independently probes every advertised Mushaf and collection recording before Pages can deploy. Media stays outside installation assets. The two complete Al-Fatihah masters in `media/` are checksum-bound native-browser decoding fixtures; they are not app installation assets.

New metadata repeats common verification fields only in code. Mushaf metadata is losslessly gzip packed and loaded on an explicit listening request; it uses the same DecompressionStream platform capability as the existing book reader. Waveform peaks are decoded from exact bytes and stored losslessly as byte strings. Round-trip tests verify both representations against their authoring JSON. No bundle ceilings or integrity checks are raised or removed.
